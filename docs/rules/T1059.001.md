# T1059.001 — PowerShell Encoded Command Execution

## ATT&CK Reference
- **Tactic:** Execution (TA0002)
- **Technique:** Command and Scripting Interpreter: PowerShell
- **ID:** T1059.001
- **Link:** https://attack.mitre.org/techniques/T1059/001/

## Why This Rule Exists
Seen in the APT investigation (Splunk lab) as a loader stage — the initial foothold payload was delivered via PowerShell with a `-enc` flag. The encoded payload decoded to a download cradle pulling a second-stage binary. This is also the primary execution method in BlackCat's initial access phase.

## Detection Logic
Detects PowerShell invocations where the command line contains encoded command flags (`-EncodedCommand`, `-enc`, `-ec`, `-e`) or where a long Base64 blob is passed as a positional argument. The Base64 regex catches cases where defenders have blocked the flags but attackers simply omit them.

## Evasion Analysis

### Baseline Rule Gap
The naive detection checks for `-EncodedCommand` as a string. Attackers commonly:
1. Use shortened aliases: `-enc`, `-ec`, `-e`
2. Omit the flag entirely and pass a raw Base64 blob as a positional argument
3. Double-encode: encode the payload, then encode the entire command again, making the outer layer look like legitimate Base64 to string-matching rules

### Why It Works
PowerShell's argument parser accepts partial parameter names. `-e` resolves to `-EncodedCommand` because no other parameter starts with "e". This is a documented PowerShell feature, not a bug — which is why it's widely exploited.

### Hardened Rule Changes
The hardened rule adds:
- All known shortened aliases via the `selection_encoded_flags` block
- A Base64 pattern regex (`[A-Za-z0-9+/]{50,}`) to catch flag-omitted variants
- A length threshold (50+ characters) to reduce false positives from short legitimate Base64 strings

### Remaining Detection Gap
Double-encoded payloads where the outer Base64 doesn't end in `=` padding characters (valid but uncommon Base64) will evade the regex. Full coverage requires script block logging (Event ID 4104), which decodes the payload before execution and logs the decoded content — a separate detection layer.

### Recommendation
Layer this rule with a Sysmon + PowerShell Script Block Logging rule (Event ID 4104 containing `invoke-expression` or `downloadstring`) for defense in depth.
